# 📦 Documentation Archive

This folder contains historical documentation that is preserved for reference but no longer actively maintained.

## 📁 Folder Structure

### `/implementation-summaries/`
**Purpose:** Historical implementation details and completion reports for completed features.

Contains documentation from:
- Dashboard CLI parity implementation
- Incremental review implementation
- Evidence enhancement features
- Pipeline integration phases

**Note:** These documents capture the state at the time of implementation. For current functionality, refer to the main documentation in `/docs/`.

---

### `/smoke-tests/`
**Purpose:** Historical smoke test reports and validation results.

Contains:
- Production smoke test reports
- E2E test assessments
- Test execution summaries

**Note:** For current testing procedures, see `/docs/TESTING_GUIDE.md` and `/tests/README.md`.

---

### `/pr-reviews/`
**Purpose:** Pull request review assessments and analysis.

Contains:
- PR assessment reports (PR #48 - #72)
- Code review findings

**Note:** These capture the review process at the time of merge. For current code, refer to the actual implementation.

---

### `/verification-reports/`
**Purpose:** Milestone verification and quality assurance reports.

Contains:
- Week 8 verification results
- Parity verification reports
- Final verification summaries

---

## 🔍 When to Reference Archives

Use archived documentation when:
1. Understanding the historical context of a feature
2. Reviewing past implementation decisions
3. Troubleshooting issues related to specific features
4. Auditing the development process

## 📝 Current Documentation

For up-to-date documentation, always refer to:
- **`/docs/README.md`** - Documentation index
- **`/docs/guides/`** - User guides and workflows
- **`/docs/architecture/`** - Architecture documentation
- **`/task-cards/`** - Current task specifications
